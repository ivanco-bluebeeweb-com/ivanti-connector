# Ivanti Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: агент service
desk, ITSM-администратор Ivanti Service Manager.

## 1. Credential type
Двойной режим: OAuth2 client-credentials (Ivanti Neurons cloud, основной путь) или
Basic Auth сервис-аккаунтом (on-prem/legacy ISM без Identity Broker).

## 2. Идеальный флоу (без ограничений SDK)
1. **Переключатель режима аутентификации первым полем** — OAuth2 vs Basic, так как это
   определяет, какие поля показывать дальше (аналог ServiceNow).
2. **Контекстные плейсхолдеры хоста** — `https://<tenant>.ivanticloud.com` для cloud,
   `https://<host>` для on-prem — сразу видно разницу форматов.
3. **Проверка через реальный запрос** к лёгкому OData-эндпоинту перед сохранением, а не
   слепое сохранение полей.
4. **Health snapshot сразу после подключения** — открытые инциденты/заявки, чтобы
   пользователь увидел живые данные, а не пустой экран.
5. **Объяснение OData query syntax при первом использовании фильтра** — `$filter=Status eq 'Open'`
   сильно отличается от привычного SQL и от AR System/JQL синтаксиса других ITSM-коннекторов
   портфеля, без объяснения пользователь не поймёт, почему его фильтр не сработал.
6. **Понятные ошибки авторизации** — при истечении OAuth2 токена явно предложить
   переподключиться, а не показывать generic 401.
